# AI Systems Lab：贯穿式学习项目

## 目标

用一个持续演进的小项目串联学习，避免同时维护多个半成品。它应是本地可运行、可测试、可观测的 LLM 服务实验台，而不是公网代码执行平台。

## 迭代顺序

1. **服务骨架**：FastAPI / Go API、健康检查、配置、测试、Docker Compose。
2. **并发与数据层**：超时、取消、任务状态、Redis 缓存、PostgreSQL 审计。
3. **本地任务执行器**：仅执行预设命令；记录时间、CPU、内存、退出码和日志。
4. **LLM 适配层**：OpenAI-compatible API、流式输出、模型切换、请求 Trace ID。
5. **评测与指标**：最小评测集、延迟/成功率指标、可复现报告。
6. **权限与多租户**：在理解 Casbin 后加入最小 RBAC/ABAC 策略；不抢在功能稳定前实现。

## 每一轮迭代的完成定义

- [ ] 有一个明确的 Issue 与不超过一周的范围。
- [ ] 本地可启动，失败场景可复现。
- [ ] 至少有一项自动化验证：单测、集成测试或压测。
- [ ] README 写清楚运行、验证和已知限制。
- [ ] 不包含密钥、个人申请材料或生产数据。

## 与目标项目的映射

| 能力模块 | 可用于展示的方向 |
|---|---|
| 任务隔离、资源限制、审计 | AI 沙盒 |
| 缓存、并发、profiling、压测 | Memory 管理 |
| 模型网关、流式响应、评测、Trace | 大模型技术服务、MindSpore |
| 鉴权、多租户、审计、模型接入 | Casbin / Casibase |
